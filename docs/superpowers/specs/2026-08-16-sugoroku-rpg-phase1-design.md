# 双六RPG フェーズ1設計: コアゲームエンジン + ローカルUI

## 背景

協力型・双六RPG(2〜8人)の新規プロジェクト。企画書の全体像は以下の通り:

- プレイヤーは一本の幹+ランダムな枝から成るエンドレスマップを進み、マスの効果でボスにダメージを与え、制限ターン以内の撃破を目指す
- 基本操作は「サイコロを振る→進む→マス効果が自動発動」のみだが、ルート選択・位置取り・キャラ固有ダイス効果などで判断の深さを持たせる
- 最終形は「ローカル(同一画面)」「同じWiFi下でのオンライン(サーバーなし)」の両方でプレイ可能、GitHub Pagesで配信

これは3フェーズに分割して進める:

1. **フェーズ1(本ドキュメント)**: コアゲームエンジン + ローカル(ホットシート)UI。ネットワークなし、1台の端末で完結する遊べるプロトタイプ
2. **フェーズ2**: WebRTC(PeerJS、無料公開シグナリングサーバー利用)による複数端末対応。ホスト端末が真の状態を持ち、他端末はホストが発行する短い接続コード(4文字以内)で参加
3. **フェーズ3**: キャラ/ボス/アイテムの拡充、配色などビジュアル調整

フェーズ2・3は本ドキュメントのスコープ外。フェーズ1のゲームロジックを「入出力が明確な純粋関数」として設計しておくことで、フェーズ2で通信層を足す際にロジックへの変更を最小化する。

## スコープ(フェーズ1)

含む:
- ランダムマップ生成(幹+枝、エンドレス拡張)
- 5種のマス(攻撃/防御/回復/アイテム/ダメージ)
- 全員同時サイコロ→移動→分岐選択→効果解決(回復→攻撃→防御→ボス攻撃の順)
- キャラクター4種(剣士/弓士/盗賊/魔法使い)、出目ごとの威力表+固有効果
- ボス1体(炎竜)、専用6面ダイス、HP、制限ターン自動算出
- プレイヤー死亡→即時復活(ペナルティ付き)
- 勝敗判定(ボスHP0で勝利、制限ターン超過で敗北)
- ホットシートUI(1端末で全プレイヤーのターンを回す)

含まない(フェーズ2/3で対応):
- ネットワーク同期
- アイテムの具体的な種類・効果の網羅(最小限のみ実装)
- キャラ/ボスの追加種類
- ビジュアルの作り込み(配色など)

## アーキテクチャ

```
index.html
style.css
src/
  mapGenerator.js   純粋関数: 幹/枝の生成、先頭側への遅延拡張
  characters.js      キャラ定義 + ダイス目ごとの威力/固有効果
  boss.js            ボス定義 + 専用ダイス表 + 制限ターン計算
  engine.js          純粋関数: 移動解決→効果解決→勝敗判定
  render.js          DOM描画(盤面・HPバー・ダイス演出)
  main.js            起動処理・キャラ選択画面・engineとrenderの結線
test/
  *.test.js          Node組込みテストランナー(node --test)によるロジック検証
```

データフローは一方向: `main.js`がUI入力を受け取り→`engine.js`の純粋関数に現在の状態を渡して次状態を計算→`render.js`が新状態をDOMに反映する。ロジックとDOM操作を分離することで、ロジック側は自動テストしやすく、フェーズ2で通信層を追加する際も「engineの入出力をネットワーク越しに送るだけ」で済む設計にする。

## データモデル(概略)

```js
GameState = {
  turn: number,
  turnLimit: number,
  boss: { name, hp, maxHp, diceTable: [6 face effects] },
  players: [
    { id, name, characterId, hp, maxHp, position: { track: 'trunk'|branchId, index }, statusEffects: [] }
  ],
  map: {
    trunk: [{ type: 'attack'|'defense'|'heal'|'item'|'damage' }, ...],  // 先頭側は遅延生成
    branches: [{ id, theme, connectFrom, connectTo, cells: [...] }]
  }
}
```

## ターン解決アルゴリズム

1. 全プレイヤーが移動ダイス(6面)を振る(ホットシートでは各プレイヤーが順にボタン押下、結果は即時確定・全員分揃うまで効果解決は行わない)
2. 出目分だけ移動。分岐点を通過する場合、その場でプレイヤーにルート選択を求める
3. マップ先頭が不足していれば`mapGenerator`が延長
4. 全員の移動が確定した時点で効果解決を以下の順で実行:
   - ① 回復マスのプレイヤー処理(周囲3マス以内の味方も回復)
   - ② 攻撃マスのプレイヤー処理(プレイヤー自身のダイスを振り、キャラ別威力表で即座にボスHPへ反映)
   - ③ 防御マスのプレイヤー処理(同一マスの味方も防御対象)
   - ④ ボスが専用ダイスを振り、全プレイヤーに攻撃
5. ボスHP0→勝利で終了。それ以外はターン数を進め、`turn >= turnLimit`なら敗北で終了(ちょうどturnLimit回のターンを与える)。継続なら1へ

同一効果内で複数プレイヤーが該当する場合はプレイヤー順(配列順)で処理する。処理順が結果に与える影響は小さいためこれで確定とする。

## バランス初期値(仮、後で調整可能)

- 炎竜: HP 300、ダイス表は企画書記載の1〜6の内容をそのまま採用(爪撃/火球×2/咆哮/全体火炎/大火炎)
- 制限ターン = `ceil(bossHP / (プレイヤー数 × 平均想定ダメージ)) × 安全係数(1.5)` で算出。平均想定ダメージ・安全係数は実装時に仮の定数として置き、コード内コメントで明示する
- プレイヤー死亡ペナルティ: 復活時HPを最大値の半分にし、次の自分のターンの効果を1回無効化する

## テスト方針

- `mapGenerator` / `engine` / `characters` / `boss`は副作用のない純粋関数として実装し、`node --test`で単体テスト(TDDで進める)
- 描画(`render.js`)は自動テスト対象外。ブラウザで実プレイして目視確認する

## 未解決点・前提
